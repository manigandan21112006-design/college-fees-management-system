================================================================================
                             ABSTRACT
================================================================================

The College Fees Management System is an intelligent web-based system
designed to streamline the process of managing student fee records,
attendance, timetables, exam results, and academic details for
educational institutions. By integrating HTML5, CSS3, Vanilla
JavaScript, Supabase (PostgreSQL), and Vercel deployment, the system
efficiently manages both administrative and student-facing operations.

The process begins with role-based authentication, allowing Admin/Staff
to manage all academic and financial records, while Students can log in
using their Roll Number and Date of Birth to view their personal
academic portal.

Administrators can manage students, fee structures, payments, subjects,
timetable, attendance, and exam results. Students can view their fee
status, payment receipts, attendance graph, timetable, exam results,
and registered courses through a dedicated 6-tab student portal.

This project enhances efficiency by automating fee tracking and
academic record management, reducing educators' workload while
maintaining quality and security. With Supabase backend storage, data
is persisted across all devices and accessible from anywhere in the
world through the Vercel deployment.

1.1 OVERVIEW OF THE PROJECT
-----------------------------

The College Fees Management System is a full-stack web application
with role-based authentication (Admin/Student), Supabase PostgreSQL
database, and a fully responsive UI built with HTML5, CSS3, and
Vanilla JavaScript. The system automates the process of managing
student records, fee structures, payments, attendance, timetables,
exam results, and course subjects.

This project includes an Admin Panel where staff can manage all
academic and financial records, and a Student Portal where students
can view their personalized academic dashboard using their Roll Number
and Date of Birth.

The system follows a structured college management format, making it
highly efficient for academic institutions. With cloud-based storage
(Supabase) and global deployment (Vercel), this project ensures
data is available from any device, anywhere in the world.

1.1.1 OBJECTIVES
-----------------

1.  Student Records Management:
    o   Add, edit, delete student records with full details.
    o   Map each student to a course, year, and fee structure.

2.  Fee Structure & Payments:
    o   Define course-wise and year-wise fee structures.
    o   Record and track student payments with receipt generation.

3.  Database Integration:
    o   Store all data in Supabase (PostgreSQL cloud database).
    o   Enable quick retrieval and modification from any device.

4.  Admin Control & Management:
    o   9-page admin panel to manage all academic records.
    o   Mark attendance, publish exam results, manage timetable.

5.  Student Portal:
    o   6-tab student portal (Home, Courses, Attendance,
        Timetable, Exam Results, Fee).
    o   Login with Roll Number + Date of Birth.


1.1.2 SCOPE OF THE PROJECT
---------------------------

6.  Admin Module:
    o   Dashboard with stats, charts, and collection summary.
    o   Manage Students, Fee Structures, Payments, Reports.
    o   Manage Subjects, Timetable, Attendance, Exam Results.

7.  Student Module:
    o   Login using Roll Number and Date of Birth.
    o   View personal fee status, attendance %, exam results.
    o   View registered subjects with codes, timetable slots.

8.  Database (Supabase - PostgreSQL):
    o   Store students, courses, fee structures, payments.
    o   Store course subjects, timetable, attendance, exam results.

9.  Payment & Receipt System:
    o   Auto-fill fee amount based on course+year mapping.
    o   Print-ready official fee receipts with college branding.

10. Export & Reports:
    o   Download Students CSV, Payments CSV.
    o   Course-wise collection reports, defaulters list.

2.3.2 Introduction to Supabase
--------------------------------

Supabase is an open-source Firebase alternative that provides a
PostgreSQL database with auto-generated REST APIs. It is used as the
backend database for this project, replacing localStorage with a
real cloud database.

Key Features of Supabase:
1.  PostgreSQL Database - Real relational database with SQL.
2.  Auto-generated REST API - No backend code needed.
3.  Free Tier - 500MB storage, unlimited API calls.
4.  Real-time capable - Changes reflect instantly.
5.  Cross-platform - Data accessible from any browser/device.
6.  Secure - Row Level Security (RLS) and API key authentication.


2.3.3 Introduction to Vercel

Vercel is a cloud platform for deploying static web applications.
The College Fees Management System is deployed on Vercel, making it
accessible globally without any server management.

Key Features of Vercel:

2.  Auto-deploy - Pushes to GitHub trigger automatic redeployment.
3.  CDN - Content delivered from edge servers worldwide.
4.  Custom domains - Supports custom domain names.
5.  HTTPS - All deployments are secured with SSL.
6.  Zero config - Detects static sites and deploys automatically.

4.3.1 Supabase REST API (Data Layer)

All API calls use the Supabase REST API via JavaScript fetch().
The db.js file manages all interactions:

  async function sbFetch(path, options = {}) {
    const res = await fetch(`${SUPABASE_URL}/rest/v1/${path}`, {
      headers: {
        'apikey': SUPABASE_KEY,
        'Authorization': `Bearer ${SUPABASE_KEY}`,
        'Content-Type': 'application/json',
      }
    });
    return res.json();
  }

Key API Endpoints and Their Functionality:

1.  GET /students
    Retrieves all student records for admin panel.

2.  GET /students?roll_no=ilike.{roll}&dob=eq.{date}
    Student login - case-insensitive roll number match.

3.  POST /students
    Adds a new student record to the database.

4.  PATCH /students?id=eq.{id}
    Updates an existing student record.

5.  DELETE /students?id=eq.{id}
    Deletes a student record (cascades to payments/attendance).

6.  GET /payments?student_id=eq.{id}
    Retrieves all payment records for a specific student.

7.  POST /attendance (with Prefer: resolution=merge-duplicates)
    Bulk upsert attendance records (insert or update on conflict).

8.  GET /exam_results?student_id=eq.{id}&order=semester,id
    Retrieves exam results for a student, ordered by semester.

9.  GET /course_subjects?course_id=eq.{id}&order=year,id
    Retrieves subjects for a student's specific course.

10. GET /timetable?course_id=eq.{id}&year=eq.{year}
    Retrieves timetable slots filtered by course and year.


4.3.2 In-Memory Cache Architecture

To keep the UI synchronous (no async calls in render functions),
data is loaded once into a cache object:

  const _cache = {
    courses, feeStructures, students, payments,
    courseSubjects, timetable, attendance, examResults
  };

  DB.load() fetches all 8 tables in parallel:
  await Promise.all([
    sbFetch('courses?order=id'),
    sbFetch('fee_structures?order=id'),
    sbFetch('students?order=id'),
    sbFetch('payments?order=id'),
    ...
  ]);

After load(), all DB.X.all() and DB.X.get() calls are
synchronous reads from _cache. Writes (add/update/delete)
hit Supabase then update the cache in place.


4.3.3 Database Schema (8 Tables)

courses:
  id, name, duration, department

fee_structures:
  id, course_id (FK), year, tuition_fee, exam_fee,
  library_fee, lab_fee, other_fee, total

students:
  id, roll_no (UNIQUE), name, email, phone, dob,
  gender, address, course_id (FK), year, status,
  admission_date

payments:
  id, student_id (FK CASCADE), fee_structure_id (FK),
  amount, paid_amount, payment_date, method,
  receipt_no, status, remark

course_subjects:
  id, course_id (FK CASCADE), year, code, name, credits

timetable:
  id, course_id (FK CASCADE), year, day, period,
  subject_code, subject_name, room, faculty

attendance:
  id, student_id (FK CASCADE), subject_code, subject_name,
  date, status
  UNIQUE(student_id, subject_code, date)

exam_results:
  id, student_id (FK CASCADE), semester, subject_code,
  subject_name, max_marks, cie_marks, see_marks,
  total_marks, grade, result


4.3.4 Security Measures

- Supabase anon key is public (publishable) - safe to expose.
- Row Level Security (RLS) disabled for simplicity.
- Admin credentials stored as plain text (suitable for demo).
- Student login uses DOB as password (Roll No + DOB match).
- sessionStorage expires when browser tab is closed.
- Admin panel redirects students away via role check.
- Student portal redirects admins away via role check.

async function handleStudentLogin(e) {
  const roll = document.getElementById('student-roll').value.trim();
  const dob  = `${year}-${month}-${day}`;

  const res = await fetch(
    `${SUPABASE_URL}/rest/v1/students?roll_no=ilike.${roll}
     &dob=eq.${dob}`,
    { headers: { 'apikey': SUPABASE_KEY, ... } }
  );
  const students = await res.json();

  if (students && students.length > 0) {
    sessionStorage.setItem('cfms_auth', JSON.stringify({
      username: students[0].roll_no,
      display:  students[0].name,
      role:     'student',
      studentId: students[0].id,
    }));
    window.location.replace('student-portal.html');
  }
}

function autoGrade(cie, see, max) {
  const pct = ((cie + see) / max) * 100;
  if (pct >= 90) return { grade: 'O',  result: 'Pass' };
  if (pct >= 80) return { grade: 'A+', result: 'Pass' };
  if (pct >= 70) return { grade: 'A',  result: 'Pass' };
  if (pct >= 60) return { grade: 'B+', result: 'Pass' };
  if (pct >= 55) return { grade: 'B',  result: 'Pass' };
  if (pct >= 50) return { grade: 'C',  result: 'Pass' };
  if (pct >= 40) return { grade: 'D',  result: 'Pass' };
  return { grade: 'F', result: 'Fail' };
}

and mobile app integration, this system has the potential to become
a complete college management solution used by multiple institutions.

and free cloud services can be combined to build a production-ready
college management system without any monthly hosting costs.
